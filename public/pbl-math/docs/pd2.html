PD-2 PRD：分年级心智模型与双视角使用手册

状态：产品/内容草案。交付物是使用手册与验证体系，不是讲义稿，也不是对儿童心智的测量报告。

1. 用户问题

学生需要知道“我在做什么、下一步是什么、失败后找谁”，而不是只看到阶段表单。教师需要知道怎样组织真实使用机会、避免 AI 代做，并正确解释受开窗、设备、公开选择和教师干预影响的数据。

现有旧手册不能替代本轮交付：最新主干改变了低段建项、账号/扫码卡、阶段配置和 AI 路径，且 manager PPT 是游戏化提案，不是使用手册。

2. 目标与非目标

目标

  • 为整体系统、教师以及一至五年级学生提供分层任务说明。
  • 每个关键任务写清入口、前置条件、步骤、完成标志、失败恢复和责任人。
  • 区分成员提交、组长推进、最终提交、结项确认、公开与互评。
  • 让教师识别“无使用机会”“埋点缺失”“设备故障”“教师干预”和“真实学习困难”。
  • 让每项目操作结论可追溯到代码、浏览器、设备或课堂证据。

非目标

  • 用年级标签推断个体能力或心理状态。
  • 通过成人代理操作证明儿童已经理解。
  • 把 visibleMs、点击密度或 AI 轮次解释为专注、兴趣或学习效果。
  • 在没有真实截图时伪造界面证据。
  • 直接覆盖正式手册或宣布所有校园设备可用。

3. 读者与使用场景

读者 使用场景 必须得到的结果
一二年级学生及协助成人 扫码、低文字建项、提交、语音/文字退路 能指出自己的项目并完成一件自己的行动
三年级学生 手动建项、调研证据、合作与反思 能说明问题选择和一条核实证据
四至五年级学生 方案取舍、制作、商业模拟、展示与迁移 能解释取舍并在无 AI 时复做关键一步
教师 课前配置、课堂组织、评价、报告、导出和复盘 不遗漏前置条件，不把系统默认分当最终判断
产品/研发/客服 定位学生或教师卡点 能按版本、角色、年级、设备和失败状态复现
内容审核者 判断文档能否发布 能区分代码事实、界面事实和待验证假设

4. 功能/内容需求

S-01 总览心智模型

手册必须解释“竞赛 → 主题 → 学生项目 → 阶段成果 → 教师评价 → 展示/成长档案”，并说明主题可关闭后三阶段，前三阶段固定保留。

S-02 学生登录与交接

分别覆盖密码和扫码路径；说明摄像头权限、无手输卡码备用路径、共享设备退出与“换一个人”。账号密码只能进入登录表单，不能输入 AI、公开作品或评论。

S-03 分年级建项

  • 一二年级：低段名称、三格必填、自动竞赛/主题选择条件和示例复制拦截。
  • 三至五年级：关联竞赛和教师主题、四格必填。
  • 无竞赛、无主题、本学期已有项目和照抄示例均需给出求助路径。

S-04 阶段、权限与完成

写清每位已接受成员可提交，组长推进阶段和发起结项；当前阶段至少有成果才可推进。最终提交与结项分开，学生最终提交后不能自行撤回，教师可按规定重开。最终提交由任一已接受成员发起，前提是每个启用阶段至少一件成果；手册必须提示学生在点击前与全组确认。

S-05 AI 使用与独立学习

推荐“首次尝试 → 请求提示 → 自己选择/修改 → 无 AI 复述或重做”。同时披露当前系统并未强制首次尝试或编辑，最近 AI 回复可能直接保存为阶段成果；工具箱 AI 还具有不同护栏与学习留痕缺口。

S-06 分年级任务卡

每个年级有独立的可观察任务、完成标志和卡住时的下一步。任务卡是验收建议，不得写成发展心理学定律。

T-01 教师课前准备

覆盖班级年级、学生导入、username 与 studentRollNo 差异、扫码卡吊销、有效竞赛、主题阶段锁、低段自动选题和目标设备检查。

T-02 课堂组织与心流

教师需先给观察与讨论机会，再开 AI；记录设备、任务布置、使用机会和线下学习。对高度相似成果先检查模板、统一口令、共同资料和 AI 代做，不直接归因为学生态度。

T-03 评价、报告与导出

说明启发式默认分、证据可见性偏差、整组同星、报告归属组长、重开副作用、前后测窗口、只读分享和高风险研究导出脚本。教师保留最终评价责任。

T-04 数据偏差与发布门槛

任何“用得少/多”“更积极”“教师导致兴趣下降”结论必须先回答分母、埋点、缺失、版本、教师干预、线下活动和独立证据。证据不足时输出“无法判定”。

5. 证据等级

标签 含义 可支撑的表述
CODE 当前提交代码已核对 “代码当前这样处理”
UI 指定版本和账号界面已操作 “在该环境看到/完成了……”
DEVICE 指定真实设备、网络和输入方式已验 “在该设备组合通过……”
CLASSROOM 获批观察/访谈/复述支持 “在该样本观察到……”，不能泛化
HYPOTHESIS 待验证心智或产品假设 “需要验证……”

CODE 不得自动升级为 UI，一次桌面成功不得自动升级为全设备 DEVICE。

6. 发布流程与门禁

代码核验草稿
  → 内容/教学评审
  → 有效隔离账号的逐角色 UI 走查
  → 指定设备与失败恢复验收
  → 小范围教师试用与学生可理解性检查
  → 负责人决定是否合并正式手册
  • 当前达到“代码核验草稿 + 登录后只读走查 + 一轮写操作走查”。设备、课堂与隐私审查仍未覆盖（见第 10 节）。
  • 任一操作没有证据时必须标待验，不得以文档完整代替运行完整。
  • 真实儿童截图、姓名、学籍号、卡码、聊天和附件不得进入发布包。
