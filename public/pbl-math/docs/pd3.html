PD-3 PRD：任务级 Agent 自主、学习证据与责任门禁

状态：独立 PPL 产品草案，供 grill；不是现有 pbl 功能说明，也不是学生生产环境开发授权。

1. 产品问题

“这个 Agent 是 L3”无法指导产品，因为同一功能中的朗读、提问、草案、发布、评价和公开可能具有不同自主程度。若只追求项目完成，Agent 还可能替代问题提出、方案选择和独立验证，使完成量掩盖没有学习。

本需求把 Agent 能力拆到任务级，并将自主程度、使用政策和学习证据放在同一个可验收闭环中。

2. 目标与非目标

目标

  • 为每个 PBL 阶段和横切动作建立任务责任卡。
  • 默认从 L0/L1 起步，只有首次尝试和独立证据满足后才允许按任务升级。
  • 支持非 Agent、苏格拉底式追问、受控草案和获批多角色对照，而非只支持聊天生成。
  • 保存 AI 来源、学生选择、实质修改、核验和无 AI 重做/迁移证据。
  • 让教师、监护人、产品和研究者在各自权限内批准、降级、停止和审计。

非目标

  • 给学生完整项目或课程的一键代做。
  • 将 L5 当作教学目标，或让 Agent 自主设学习目标并自动评价学生。
  • 用聊天轮次、文本长度、作品数量或使用时长代替学习。
  • 自动作出最终评价、纪律、安全、公开、监护同意或隐私决定。
  • 未经验证向所有年级、地区和家庭推广同一策略。

3. 角色与权限（拟议）

角色 可以做什么 不能做什么
学生 首次尝试、请求允许的帮助、选择/拒绝、修改、复述、重做和迁移 自行提高任务 L 级；把 AI 输出冒充独立成果
教师 设学习目标、任务边界和阶段上限；审查证据；确认评价；降级/停止 将成人点击批准当作学生已经参与
监护人 在 C 端获批范围内开通、查看最小摘要、撤回和删除 代替孩子完成核心任务或授权超范围数据
教研/研究负责人 定义任务量规、对照条件、独立证据和研究停止点 用互动热度证明效果
产品/研发 配置注册表、策略执行、来源和审计 通过技术默认绕过人类审批
数据/合规负责人 审批数据、模型提供方、保留、跨境和删除 将敏感数据授权转交给 Agent

这些角色和权限是目标产品需求，不是当前 pbl 已有能力。

4. 核心对象：任务责任卡

每个任务在运行前必须有唯一记录，字段如下：

字段 必填内容
taskId/stage/gradeBand 具体任务、PBL 阶段和适用年级
learningObjective 学生要学会什么，而不是页面要完成什么
initiator 学生、教师、系统或 Agent；学生正式流程默认不允许 Agent 自主发起
decisionRights 谁决定目标、方案、继续、公开和评价
executionScope Agent 可执行的具体步骤和禁止步骤
autonomyLevel L0–L5；阶段关闭时为 N/A
usagePolicy ALLOWED/HUMAN_ONLY/RESEARCH_ONLY/FORBIDDEN
firstAttempt Agent 介入前学生必须完成的动作和证据
approvalGranularity 每一步、每一草案、每一项目或每一发布动作
independentEvidence 复述、修改、错误纠正、无 AI 重做和迁移要求
stopDowngrade 触发条件、降到何级、谁负责和审计位置

缺少任一核心字段时任务为 NOT_READY，不能进入学生环境。实际允许等级取阶段、年级和当前证据上限的最低值；Agent 不能自行升级。

5. 功能需求

FR-01 任务注册与政策包

  • 支持六阶段和横切动作分别配置，不给整个 Agent 永久等级。
  • 年级上限是待验证政策起点，不作为认知定律。
  • 任何变更需版本化；历史任务保留当时政策和模型信息。
  • 非 Agent 路径是正式选项，L0 不等于产品失败。

FR-02 首次尝试门禁

  • 核心学习任务在 Agent 介入前记录学生初稿、猜想、口头说明或操作尝试。
  • 未满足时只允许 L1 无障碍/输入辅助或帮助学生理解“如何开始”的提示，不生成核心答案。
  • 教师不能通过批量点击替学生制造首次尝试。

FR-03 交互模式

模式 允许任务 默认限制
非 Agent 创作、编辑、模拟、搭建、练习和展示 必须保留完整可用路径，作为对照
苏格拉底式 学生先尝试后的提问、线索、反例和检查 默认 L2；不直接替学生回答核心问题
草案协同 教师项目草案、学生成熟后局部方案比较 草案 L3；逐项审查、来源、修改和理由
多角色讨论 获批研究中的利益相关者/反方视角 L2–L3；角色不得冒充权威来源
多步事务执行 成人批准目标下的格式、归档等非核心事务 可评估 L4；检查点和验收不可省略
自主闭环 仅限合成成人研究 学生正式流程 FORBIDDEN

FR-04 来源、保存与修改

  • AI 输出必须带任务、模型、时间、来源类型和对应学生首次尝试的关联。
  • 保存 AI 内容为成果前，要求学生选择采纳/拒绝、作出有意义修改并说明理由。
  • 不能只改标点或点击保存；具体“有意义修改”由任务量规判断，不能仅用字数差。
  • 最近一条 AI 回复不能绕过收口、修改和证据要求直接成为最终学习成果。

FR-05 独立检查

  • 学生需在无 Agent 条件下复述核心选择、重做关键一步或完成相邻迁移任务。
  • 含可核验错误的合成回答用于测试学生能否发现、查证和纠正。
  • 未通过时任务标为需要教学/降级，不标为“完成且掌握”。
  • 独立检查不自动生成最终学科评价，教师保留责任。

FR-06 人类审批

最终评价、纪律、安全处置、监护同意、隐私范围、外部数据处理、公开分享和作品发布必须单独配置责任人。自动批准草案和批量确认评价默认 FORBIDDEN，除非逐项审批、留痕并重新验收。

FR-07 降级、停止与恢复

出现直接索答、无法复述、无实质修改、来源不可核验、隐私/安全信号或模型异常时立即停止当前帮助并降到 L0/L1。恢复需由责任人复核新证据，Agent 不得自行恢复。

FR-08 成人可见与最小数据

C 端监护人默认只看到孩子选择的学习证据、AI 使用摘要和必要风险提醒，不默认获得无限监控、情绪识别或公开排名。原始语音、图像、自由文本和聊天正文是否保存需独立审批，不作为责任卡的隐含副作用。

FR-09 对照研究

同年龄、同任务、同情境比较 L0、L2、L3 和多角色条件，固定内容、轮次预算、设备和时间。主要结果为独立复述、错误纠正、实质修改和迁移；消息数量、完成速度和满意度仅为辅助指标。

6. 目标流程与状态（拟议）

NOT_READY
  → READY
  → FIRST_ATTEMPT_RECORDED
  → ASSISTANCE_ACTIVE
  → STUDENT_REVISION
  → INDEPENDENT_CHECK
  → COMPLETE

任意帮助阶段 → DOWNGRADED / BLOCKED
L0 路径 → FIRST_ATTEMPT_RECORDED → INDEPENDENT_CHECK → COMPLETE
  • 状态用于防绕行，不代表当前系统已有这些字段。
  • 返回修改不能自动清除此前的 AI 来源和降级记录。
  • 成人批准与学生独立证据是两个并行条件，不能互相替代。

7. 成功指标与反指标

类型 指标
学习证据 无 AI 复述、关键步骤重做、相邻任务迁移、错误发现和纠正
主体性 学生能说明采纳/拒绝理由和关键取舍
安全 未授权公开、自动评价、敏感数据外传和越级执行为零
可用性 学生知道何时不用 AI；非 Agent 退路可完成任务
反指标 聊天更长、消息更多、作品更多、Agent 完成率更高

若完成率提高而独立迁移不提高，不能判为学习产品成功；若 L0 与 Agent 条件没有学习差异，应保留非 Agent 方案。

8. 分阶段交付

阶段 交付 门禁
M0 合成政策包 六阶段责任卡、风险清单、合成任务与人工双评审 定义分歧未裁决则不开发
M1 交互原型 非 Agent + L2 + L3 对照、来源/修改/独立检查记录 只用合成数据；越级即失败
M2 获批教学研究 小样本课堂观察、访谈、复述和迁移 同意、退出、删除和模型审批齐备
M3 C 端场景试验 从市场调研选择一个窄场景，验证使用与付费 不因 M2 完成自动商业化；另做地区和设备门禁

9. 验收

沿用 Project Description 的 T-01 至 T-08，并增加：

  • 未记录首次尝试时，核心生成请求被拒绝。
  • 学生无实质修改或不能复述时，成果不能标为独立掌握。
  • 自动公开、自动评价、自动批准和 Agent 自行升级均被拒绝并留审计。
  • L0 路径可完成同一学习目标，且不被界面故意弱化。
  • 多角色若只增加成本/消息而不增加迁移，停止扩展。
  • 原始内容未获批准时，系统仍能以最小元数据运行或明确不进入研究。
