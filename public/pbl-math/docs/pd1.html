PD-1 PRD：学习证据、偏差分析与只读语义回放

状态：产品草案，供 grill；不是生产采集、真实儿童研究或开发授权。

1. 背景与问题

产品经理需要知道学生在哪些关键任务上暴露、尝试、受阻、恢复和提交，教师需要避免把数据缺口误读成学习问题。当前代码已有部分 LearningEvent，但密码登录漏记、客户端失败静默丢失、跨页面会话关联不足、工具箱 AI 未入学习证据，且没有回放器。

因此，本需求不是“记录一切”，而是建立一个能明确显示已知、未知、缺失和替代解释的学习证据工具。

2. 产品原则

  1. 先回答研究问题，再决定字段；没有明确用途的字段不采集。
  2. 先合成数据，再测试服合成身份；生产聚合与个体时间线分别审批。
  3. 页面可见时长不是注意力，事件密度不是兴趣，提交完成不是理解。
  4. 回放只读；不得重放原请求、恢复登录态或调用业务写入。
  5. 回放必须展示缺口、重复、乱序和版本差异，不生成看似完整但未经证明的轨迹。

3. 目标与非目标

目标

  • 用统一事件字典描述关键学习任务的暴露、尝试、失败、恢复、提交和教师干预。
  • 提供带使用机会分母、缺失说明和混杂因素的聚合分析。
  • 让获批查看者在另一台设备上查看同一段合成 session 的只读时间线。
  • 在分析前暴露丢包、重复、乱序、版本差异和不可观测路径。

非目标

  • 全量 DOM、像素、自由文本、声音或触摸录制。
  • 自动识别走神、情绪、兴趣丧失或真实理解。
  • 教师或学生排名、自动纪律处置、教师绩效结论。
  • 用 AI 使用次数或聊天长度证明学习效果。
  • 生产数据导出、真实学生明细访问和全量追踪的默认开通。

6. 功能需求

FR-01 事件与研究字典

每个事件必须登记：研究问题、事件含义、触发角色、使用机会分母、允许字段、数据所有者、保留期、版本和删除方式。未知用途、未知保留期或任意 JSON 透传均不得通过评审。

FR-02 会话与数据质量

后续实现需覆盖密码/扫码登录成功与失败、退出、标签页、刷新、序号、幂等和版本。质量面板至少区分：未观测、未发生、无使用机会、上传失败、重复、乱序和时钟不可信。

FR-03 合成回放导入

  • 仅接受符合 spec.md 的合成文件。
  • 默认拒绝整个不合格文件，不将部分敏感内容“清洗后展示”。
  • 页面只显示拒绝类别和数量，不回显被拒绝的字段值。
  • 非合成文件、未知 schema 版本和未知事件字段必须拒绝。

FR-04 只读时间线

  • 按登录会话和标签页展示事件顺序、结果、停止点和缺口。
  • 重复事件折叠并标记；乱序事件保留原始序号与文件顺序差异（M1 合成文件的数组顺序不代表网络到达顺序）。
  • 无跨标签页可靠顺序时并排展示，不合成一条伪连续轨迹。
  • 每个结论可追溯到事件 ID；缺失结论必须标“无法判定”。

FR-05 聚合与偏差报告

每个指标必须带：符合资格人数、实际获得任务人数、打开页面人数、尝试人数、成功人数和可观测人数。教师干预、设备故障、公开选择和默认评价需要作为混杂因素显示。

口径约束（与 spec §8.1 一致）：

  • 符合资格人数取自班级名册，包含没有建项目的学生；不能拿“机会表”的行数当分母，否则正好漏掉“无使用机会”那一组，使用率会被系统性高估。
  • 实际获得任务人数只能给下限：Project.currentStage 记的是“走到了哪”，不是“被布置了什么”。真实的“被布置”来源（班级级布置记录）尚未确定，见 D8。
  • 成功不是“有没有一条推进事件”，而是“阶段已通过”：reachedStage > k 或回放里有 ref.stage = k 的 stage_advance，二者取或。推进事件会因 track() 吞错而丢，但项目状态在事件之前就已写库。
  • 停止点分三态（已完成 / 进行中 / 停滞），另加“无使用机会”和“未观测”，不使用“第一个没有推进事件的阶段”这种算法。

FR-06 访问与撤回

跨设备查看必须鉴权、记录访问审计并设置有效期。撤回后不能再打开分享；删除覆盖获批范围内的数据库、导出、日志、对象存储、备份和第三方处理面。任何一面不可定位即不得进入 M2/M3。

FR-07 拒答与替代解释

以下输出必须由产品阻止：学生走神/失去兴趣、教师指挥不力、学生真正理解、AI 提升学习效果。系统可提示需要的课堂观察、访谈、独立复述或迁移任务，但不能自动生成这些结论。

7. 页面与状态

  • 空状态：说明没有合成文件或没有已授权 session，不显示“学生没有学习”。
  • 校验失败：显示稳定错误类别和修复建议，不显示敏感原值。
  • 缺段：显示缺口范围与可能原因，不自动补事件。
  • 多标签页：分组显示，跨组顺序不明时明确标注。
  • 版本不兼容：拒绝导入并显示支持的 schema 版本。
  • 授权过期：停止查看并关闭缓存访问；不保留可绕过的新公开链接。

8. 验收

M1 至少通过 project-description.md 的 V-01、V-02（仅限合成文件可表达的缺口、重复、乱序、跨标签页；时钟偏移只以 timeConfidence 表达）、V-04、V-09，以及 spec 除 F-08 外的全部参考 fixture。其中 F-11 必须按 spec §8.1 的名册表 + 机会表口径复算，逐格对得上才算通过；只“跑通”不算。M2 另需 V-03、V-08 和 F-08。V-05 随 A-04 生产版进入 M3；V-07 随研究线 A-07。V-04/V-06 验证报告语言与分母，不得用合成数据宣称生产结论。

完成定义不是“页面能打开”，而是：敏感输入被拒绝、时间线不重放写入、缺口可见、跨设备权限可撤回、测试结果可复现。

9.2 D7 落地条款（草案，待签）

权限分离不是一句话，要落成四个角色，任何一个人都不能同时占住“签发、保管、执行”中的两项：

角色 能做 不能做
授权签署人（数据负责人） 签发“某个合成 session + 某个查看者 + 有效期” 不得是仓库管理员；不得持有导出密钥；不得执行导出
密钥保管人 保管项目级与批次级密钥，按批次交付给执行人 不得签发查看授权；不得独自执行导出并拿走结果
导出执行人 在获批范围内运行导出脚本，登记批次号 不得自己签发授权；不得长期留存密钥
回放查看者 在有效期内查看被授权的合成 session 不得导出、不得分享公开链接

补充规则：

  • 每一次导出必须留下“批次号 + 授权单号 + 执行人”记录，缺一项视为未授权导出。
  • 如果现实里只能找到一个人承担上述全部角色，M3 不启动；M1、M2 不受影响，因为它们不导出真实数据。
