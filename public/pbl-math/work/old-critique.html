方法上为什么不合格

证据没有封口

“同上”“记忆库”“后台调研”无法让另一位评审复现。新稿统一分成四类：代码事实、运行证据、负责人提供的背景、待验证假设。只有前两类可以支撑现状结论。

验收不是可判定测试

“负责人体验后验收”没有预设输入、步骤、期望结果和停止条件。新稿必须逐项包含环境、操作、期望和失败时停止点；复核中发现的缺项需先补齐，不能自称已经满足。验证等级 L1–L4 仅指静态、行为、构建、真实环境，与 Agent 自主等级完全无关。[文档: docs/testing-strategy.md:25-38]

偏差被误写成原因

“使用少”“点击多”“提交少”只是观察结果，不足以唯一推出不能用、不会用、不想用或教师组织问题。新稿要求先列使用机会、分母、缺失率和替代解释，再决定是否需课堂观察或访谈。

隐私被当成文档章节，而非停止条件

《个人信息保护法》第 28 条将不满 14 周岁未成年人的个人信息列为敏感个人信息；第 31 条要求取得父母或其他监护人同意并制定专门规则。[来源: 1-PIPL] 因此“先录下来再讨论用途”不是可接受路径。是否需要处理、处理哪些字段、保存多久、谁能看、如何撤回与删除，未批准前均不得上生产。

Agent 等级混淆

旧稿同时使用验证 L1–L4、数据层 L0–L5 和 Agent 能力，却没有说明它们不是同一把尺子。新独立项目只把 L0–L5 定义为任务自主程度，并额外记录学生责任、教师责任、数据风险和独立学习证据。
