PROBLEM / 两条死路

为什么截图方案总在关键时刻掉链子

A 重模型 + 截图

看得懂，但每一步都在烧钱和赌坐标。

  • 贵且慢：每一步都要送一张图，长任务很快烧穿预算。
  • 坐标漂移：DPI 缩放、窗口移动、分辨率一换就偏。
  • 主题敏感：换肤、深色模式、字体变化要重做模板。
  • 抢焦点：挪鼠标、抢前台，人机不能并行。

B 轻模型 + 猜测

便宜快，但看不清就等于闭着眼点。

  • 小字看不清：微信、登录器、老 ERP 的界面全是自绘。
  • 0 个控件：DirectUI 在 UIA 树里可能一个元素都不暴露。
  • 自信地错：点偏了不报错，继续往下执行。
  • 遮挡即失效：窗口被挡一半，截图里只剩半张脸。
DPI 缩放深色模式窗口遮挡焦点抢占中文输入法 原话：要么贵又慢，要么快但瞎。
来源：视频 00:00–00:12、README 痛点表03 / 12

PATH 03 / 自绘软件

微信这种「零控件」界面，靠词级 OCR 点准

  • 0 个 UIA 控件：DirectUI 自绘界面，传统 UIA 直接失效。
  • 离线词级 OCR：Windows 11 原生 zh-Hans-CN，按词返回坐标。
  • 子串匹配：「编辑 查看 帮助」能只点「编辑」，不点整行中点。
  • 外置标尺：黄色刻度就是真实桌面坐标，0% 遮挡窗口内部。
  • 遮挡即拒绝：窗口被挡时返回 OCR_OCCLUDED，不猜。

SAFETY / 12 道门

安全不是口号：失败就停，不猜着点

SELF_TARGET_BLOCKED拒绝操作 Agent 自己的窗口
UIPI_BLOCKED目标以管理员运行，权限不够
OCR_OCCLUDED窗口被遮挡，拒绝读屏
STALE_SNAPSHOT控件树已变，旧引用失效
AMBIGUOUS_TARGET重名目标，不猜是哪一个
PASTE_UNVERIFIED回读失败，自动拦下回车
OPERATION_ID_CONFLICT重放 / 冲突请求被拒
SEARCH_INCOMPLETE搜索结果被截断，不当作完整

为什么这些门重要

  • 12 项硬门禁全绿（作者双模型两轮审计）
  • 0 物理鼠标移动
  • 0 真实剪贴板改动
  • 7 个旁路工具双重禁用

原则：宁可不做，也不乱点。失败必须是一个明确的错误码，而不是「看起来成功了」。

LIMITS / 边界

三个代价，视频里没展开

01

它是 fail closed 的

不暴露 UIA、又不能 OCR 的界面，headless 路径直接没有；只能退回 --headed 物理输入或坐标点击。

02

OCR 是兜底，不是万能

依赖 Win11 中文语言包；动画、低对比度、被遮挡都会失败，而且 OCR 本身有延迟。

03

账号风险要自己担

评论区有实测反馈：自动化操作微信会触发强制退出登录。先用小号、只读流程试。

另外：目标窗口以管理员权限运行时，标准权限的 MCP 会被 UIPI_BLOCKED 挡下。

适合：重复、可回读、失败了能重来的流程。不适合：一次都不能错、且无法人工复核的操作。

来源：README 限制、评论区实测反馈、Windows UIPI 机制10 / 12
