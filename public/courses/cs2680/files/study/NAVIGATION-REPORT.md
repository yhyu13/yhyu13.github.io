## 2. What was added

| file | what it is |
|---|---|
| `concepts.html` | 27-slide html-ppt deck: the course in one page, then 143 concepts in 13 groups, each linked to the exact slide that teaches it |
| `concepts.mjs` | the concept data, plus the "course in one page" facts; every string is checked against the digest at build time |
| `search.html` | 2-slide page: a live search box over the whole site, plus its provenance slide |
| `search-index.json` | the static index the search page reads (212 slides + 433 course-text pages) |
| `check-links.mjs` | the broken-link checker used below |
| `build.mjs` | extended: generates `concepts.html`, `search.html` and `search-index.json`, renders the new index learning path, validates the concept strings against the digest |
| `index.html` | regenerated by `build.mjs` - new learning-path slide, new "Course tools" slide, links to both new pages |

**Concept index.** 143 concepts, grouped by the digest's lecture order and
labelled with the course's own Part I / Part II split (plus "Reference notes"
and "Course mechanics"). Each row carries a concept name, the digest sentence
it comes from, and one or two deep links of the form
`decks/lecture-04.html#/7`. The page opens with the course in one page: the
thesis, Part I and Part II with their topic lists, the five Mads assignments
with weights and dates, and the evaluation / cost trade-off.

**Search.** Searches the visible text of all 212 slides (speaker notes
excluded) and the mirrored course text in `course/notes/*.md` and
`course/slides/*.txt`. Results show the deck name, the slide number, the
slide title, the matching text with the hit highlighted, and a link to
`decks/<deck>.html#/N`. A course-text hit links to the deck built from that
file and, where the same words appear on a slide, to that slide as well. The
page carries the index inline so it works from `file://` with no server, and
falls back to fetching `search-index.json` if the inline copy is absent.
`search.html?q=<query>` opens the page already searching.

**Index learning path.** "How to use this site" became "Three ways through
the course": Route A fast orientation (4 slides), Route B the standard pass
(the published Part I in order, 10 decks), Route C a deep route by system
concern (context, memory, multi-agent, evaluation, cost, reliability). Every
stop is a specific slide, not a deck's first page. The original keyboard and
reading notes were kept on a separate "How this site works" slide.

## 3. Verification

### Build and determinism

```
node build.mjs          -> built 14 decks + index.html + concepts.html + search.html
node build.mjs (again)  -> 0 file(s) changed        (deterministic)
node build.mjs --check  -> number check: every number on every page appears in the course digest.
```

`build.mjs` now refuses to run if any concept term, gloss or "course in one
page" string is not a verbatim substring of `courseware/_digest/`. That check
is what guarantees no invented fact reached the new pages.

### Slide-count check, before and after

```
decks: 14 before / 14 after ; slides: 212 before / 212 after ; mismatches: 0
```

`git status` confirms the 14 deck files are not in the modified set - they are
byte-identical to the files that existed before this work.

### Broken links

`node check-links.mjs` walks every relative link on `index.html`,
`concepts.html` and `search.html`, plus every deep link inside
`search-index.json`. For each `decks/<deck>.html#/N` it checks that the deck
file exists **and** that the deck has at least N slides.

```
checked 909 link(s) across 3 page(s) plus the search index
broken links: 0
```

### Deep-link proof

`decks/lecture-04.html#/7` loaded in headless Edge at 1600x900 renders the
slide titled "Five more tools, five design rules", and the deck footer reads
**7 / 20**. The concept index links into that same deck, and the checker
confirms every `#/N` target resolves inside a deck of at least N slides.

### Visual check

Rendered in headless Edge (`--headless=new --window-size=1600,900
--virtual-time-budget=8000`) against `python -m http.server 8931`, and the
PNGs were inspected. Four defects were found and fixed, then re-rendered:

1. **Index learning-path slide - title overlapped the deck header.** The
   three route cards made the slide taller than its content box; because the
   slide is flex-centred, the overflow was clipped at the top and the title
   ran into the header. Fixed by making the slide top-aligned, dropping the
   per-stop subtitle on Route B, and tightening the card and list metrics.
2. **Concept group slides - lopsided and sparse.** The first chunker split a
   12-concept group into 9 and 3, leaving a three-row slide. Replaced with a
   deterministic balanced chunker sized to the real per-slide capacity; the
   smallest concept slide is now 5 rows and the tallest (Lecture 7, 11 rows)
   fits without clipping.
3. **Search page - oversized title and an empty results area.** The title was
   reduced and the empty state now carries a "What is indexed" panel and ten
   clickable example queries.
4. **Assignments table on the concept index - columns ran together.** The
   Title column butted against the Weight column. Fixed with `table-layout:
   fixed`, explicit column widths and wider cell padding.

A further fix was needed for correctness rather than layout: `concepts.html`
initially pointed at `../assets/...`, but it sits at the site root, so the
stylesheets were not loading. The link checker caught it (4 broken links);
the paths are now `./assets/...`.

Final pass: no content touches the top or bottom edge, no columns overlap,
and no page is clipped on any of the rendered slides.

## 4. Notes and limits

- The task described the mirrored course text as `courseware/notes/*.md` and
  `courseware/slides/*.txt`. Those directories do not exist; the mirrored text
  lives in `course/notes/*.md` (27 files) and `course/slides/*.txt` (9 files).
  The build reads them from there - read-only - and writes only into
  `courseware/html/`.
- The concept index and the index learning path contain editorial choices:
  which slide teaches which concept, and which slides a route visits. Those
  are navigational decisions, not course facts. Every fact, number, date,
  weight and name on the new pages comes from the digest and is checked
  against it at build time.
- `search-index.json` is 1.29 MB and `search.html` 1.31 MB, because the page
  carries the index inline so it works without a server. `search.html` will
  fetch `search-index.json` instead if the inline copy is ever removed.
- `git status` also shows pre-existing modifications to `courseware/remotion/`
  and `tools/`. Those were already in the working tree before this task and
  were not touched.
