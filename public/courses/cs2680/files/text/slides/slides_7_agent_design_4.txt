Metrics
• Earlier benchmarks
• Perplexity: exponentiated average negative log-likelihood on held-out text (lower is better)
• Accuracy or F1 score
• Preference or win rate
• Capability
• Pass@k: at least one out of k solutions passes
• Pass^k: all k solution passes (introduced by τ-bench)
• Cost
• Mostly LLM cost
• Overlooked: tool calls and others (e.g., LLM cache miss)
• Latency/duration
• Not just LLM

Leakage can occur through the whole agent stack
Modern “agent” performance is roughly a function of
𝑃 =  𝑓(LLM, prompt, scaffold, tools, retriever, memory, environment)
Component
Possible leakage
Base model
Benchmark examples in pretraining
Fine-tuning
Benchmark solutions used as agent-training trajectories
Prompt
Few-shot examples derived from test tasks
Retrieval
Benchmark answers indexed in RAG corpus
Memory
Previous benchmark attempts stored
Web search
Published task solutions retrieved
Environment
Future Git commits / hidden artifacts exposed
Scaffold
Hand-coded heuristics tuned to benchmark
Agent development
Researchers repeatedly inspect test failures and tune the system
Any one of these can contain benchmark information. Therefore saying “the model was not trained 
on the test set” is nowhere near sufficient for agent evaluation.

Challenges with Agent Evaluation: a single user turn
• Most benchmarks hand the agent one fully-specified instruction
• prompt in, final state out — no user in the loop
• Real work is ambiguous, revised and interrupted
• missing constraints, mid-task corrections, shifting goals
• Single-turn scoring rewards confident guessing
• asking a clarifying question costs steps and earns no credit
